# 📋 Plan de Acción — Sistema OCR Inteligente para Digitalización de Contratos
**Stack:** .NET 8 / C# · ASP.NET Core Web API · Python (entrenamiento) · ONNX Runtime · React (frontend)  
**Versión del plan:** 1.0 — Junio 2026  
**Elaborado para:** Equipo técnico interno

---

## 🗺️ Visión general del sistema

El sistema tendrá tres grandes componentes:

1. **Modelo de IA (OCR de DNI):** entrenado en Python, exportado a ONNX, consumido desde C#
2. **Backend API:** ASP.NET Core que orquesta todo el flujo (recibir foto → extraer datos → generar contrato → servir PDF)
3. **Frontend de RH:** interfaz simple (tablet/PC) donde el operador toma la foto, confirma datos y manda a imprimir

---

## 📦 Stack tecnológico completo

| Capa | Tecnología | Motivo |
|---|---|---|
| Lenguaje backend | C# / .NET 8 | Stack definido, multiplataforma, LTS |
| Framework API | ASP.NET Core Web API | REST, robusto, fácil de desplegar en Windows |
| OCR / Inferencia | ONNX Runtime para .NET (`Microsoft.ML.OnnxRuntime`) | Corre modelo Python exportado sin deps externas |
| Entrenamiento del modelo | Python 3.11 · PaddleOCR | Mejor OCR open source para documentos en español |
| Exportación a ONNX | `paddle2onnx` | Convierte modelo al formato que consume .NET |
| Preprocesamiento de imagen | OpenCV (Python/entrenamiento) · ImageSharp (C#/runtime) | Normalización, deskew, contraste |
| Generación de contratos | QuestPDF (C#) | Genera PDF del contrato con datos rellenados |
| Base de datos (logs) | SQLite | Guardar registros de contratos generados |
| Frontend operador | React + Vite | Interfaz para RH: cámara, confirmación, imprimir |
| Captura de imagen | WebRTC (API de cámara del navegador) | Fotografiar el DNI desde tablet/PC |
| Comunicación | HTTP/JSON REST | Simple, bien soportado |
| Despliegue | Windows con Kestrel standalone o IIS | Sin costo adicional de infraestructura |
| Control de versiones | Git | Versionado del código y del modelo |

---

## 🔀 Flujo completo del sistema (en producción)

```
[RH abre app en el navegador del tablet/PC]
    → [Toma foto del DNI con cámara web vía WebRTC]
    → [Frontend envía imagen al backend vía HTTP POST]
    → [Backend preprocesa imagen (normaliza, recorta, ajusta contraste)]
    → [Modelo ONNX infiere: extrae campos del DNI]
    → [Backend retorna JSON con los campos extraídos]
    → [Frontend muestra datos para confirmación + campo "nivel educativo" manual]
    → [RH confirma / corrige si hay algo incorrecto]
    → [Frontend envía datos confirmados al backend]
    → [Backend aplica datos a la plantilla del contrato]
    → [Backend genera PDF del contrato listo]
    → [Frontend muestra PDF y lanza impresión]
    → [Trabajador firma y pone huella en papel impreso]
```

## ✅ FASE 2 — Entrenamiento del modelo OCR de DNI
**Duración estimada:** 4–6 semanas  
**Objetivo:** Tener un modelo de IA capaz de recibir una foto de DNI y devolver un JSON con todos los campos extraídos, con precisión >= 95%.

### 2.1 Estrategia del modelo

**Enfoque seleccionado: PaddleOCR con fine-tuning**

PaddleOCR es el OCR open source con mejor desempeño en documentos de identidad latinoamericanos. El enfoque será:
1. Usar PaddleOCR preentrenado como base (ya sabe leer texto)
2. Fine-tunear con imágenes de DNI peruano para mejorar precisión en ese dominio
3. Agregar una capa de **extracción de campos**: dado el texto detectado, asignarlo al campo correcto (nombre, apellido, DNI, etc.)

### 2.2 Preparación y anotación del dataset

- Usar **Label Studio** (open source, corre local) para anotar:
  ```bash
  label-studio start
  ```
- Anotar cada imagen marcando los bounding boxes de cada campo:
  - `nombres`, `apellido_paterno`, `apellido_materno`, `dni`, `fecha_nacimiento`, `sexo`, `direccion`, `ubigeo`
- Exportar anotaciones en formato PaddleOCR (txt con coordenadas y texto)
- División del dataset:
  - 70% entrenamiento (`train/`)
  - 15% validación (`val/`)
  - 15% test final (`test/`)
- Script de augmentación de datos (multiplicar el dataset x5 sin más fotos reales):
  ```python
  # augmentation.py — aplicar a imágenes de entrenamiento:
  # - rotaciones leves (±5°)
  # - variación de brillo/contraste
  # - blur leve (simula cámara desenfocada)
  # - ruido gaussiano
  # - recortes con padding (simula encuadres distintos)
  ```

### 2.3 Pipeline de preprocesamiento de imagen (Python)

```python
# preprocess.py
import cv2
import numpy as np

def preprocess_dni(image_path):
    img = cv2.imread(image_path)

    # 1. Convertir a escala de grises
    gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)

    # 2. Deskew (corregir inclinación leve con Hough Transform)

    # 3. Normalizar contraste (CLAHE - maneja sombras y zonas oscuras)
    clahe = cv2.createCLAHE(clipLimit=2.0, tileGridSize=(8,8))
    enhanced = clahe.apply(gray)

    # 4. Binarización adaptativa (para manejar reflejos)
    binary = cv2.adaptiveThreshold(enhanced, 255,
                                    cv2.ADAPTIVE_THRESH_GAUSSIAN_C,
                                    cv2.THRESH_BINARY, 11, 2)

    # 5. Resize a dimensión estándar
    resized = cv2.resize(binary, (800, 500))

    return resized
```

### 2.4 Entrenamiento del modelo

**Paso A — Detección de regiones (dónde está cada campo):**
```bash
python tools/train.py -c configs/det/ch_PP-OCRv4_det_student.yml \
    -o Global.pretrained_model=pretrain_models/ch_PP-OCRv4_det_distill_train \
    Global.save_model_dir=./output/dni_det/
```

**Paso B — Reconocimiento de texto (qué dice cada región):**
- Fine-tunear el modelo de reconocimiento con crops de texto del DNI peruano
- Los DNIs usan fuente OCR-B estándar, lo que facilita el reconocimiento

**Paso C — Post-procesamiento y asignación de campos:**
Reglas heurísticas para asignar texto al campo correcto:
- 8 dígitos numéricos consecutivos → número de DNI
- Formato DD/MM/YYYY en zona superior → fecha de nacimiento
- Texto "M" o "F" en posición conocida → sexo
- Texto en zona superior izquierda → nombres/apellidos (por posición relativa)

### 3.4 Preprocesamiento de imagen en C# (ImageSharp)

```csharp
// Services/ImagePreprocessingService.cs
using SixLabors.ImageSharp;
using SixLabors.ImageSharp.Processing;

public class ImagePreprocessingService
{
    public byte[] Preprocess(byte[] inputImage)
    {
        using var image = Image.Load(inputImage);

        image.Mutate(ctx => ctx
            .AutoOrient()          // corregir orientación EXIF
            .Grayscale()           // escala de grises
            .Contrast(1.2f)        // aumentar contraste
            .Resize(800, 500)      // tamaño estándar para el modelo
        );

        using var ms = new MemoryStream();
        image.SaveAsPng(ms);
        return ms.ToArray();
    }
}
```

### 3.6 Generación del contrato con QuestPDF

```csharp
// Services/ContractService.cs
using QuestPDF.Fluent;
using QuestPDF.Infrastructure;

public class ContractService : IContractService
{
    public byte[] GenerateContract(ContractData data)
    {
        return Document.Create(container =>
        {
            container.Page(page =>
            {
                page.Size(PageSizes.A4);
                page.Margin(2, Unit.Centimetre);

                page.Content().Column(col =>
                {
                    // Encabezado
                    col.Item().Text("CONTRATO DE TRABAJO")
                       .Bold().FontSize(14).AlignCenter();

                    col.Item().PaddingTop(10);

                    // Datos del trabajador (autollenados)
                    col.Item().Text($"Apellidos y Nombres: {data.NombreCompleto}");
                    col.Item().Text($"DNI: {data.NumeroDni}");
                    col.Item().Text($"Fecha de Nacimiento: {data.FechaNacimiento}");
                    col.Item().Text($"Sexo: {data.Sexo}");
                    col.Item().Text($"Dirección: {data.Direccion}");
                    col.Item().Text($"Nivel Educativo: {data.NivelEducativo}");
                    col.Item().Text($"Cargo: {data.Cargo}");
                    col.Item().Text($"Área: {data.Area}");
                    col.Item().Text($"Fecha de Inicio: {data.FechaInicio}");

                    // Cuerpo del contrato (cláusulas)
                    // ... agregar el texto legal del contrato real aquí

                    // Espacio para firma y huella (físicas)
                    col.Item().PaddingTop(50).Row(row =>
                    {
                        row.RelativeItem().Column(c =>
                        {
                            c.Item().BorderBottom(1).Height(40).Text("");
                            c.Item().Text("Firma del Trabajador").AlignCenter();
                            c.Item().Text($"DNI: {data.NumeroDni}").AlignCenter();
                        });
                        row.ConstantItem(30);
                        row.RelativeItem().Column(c =>
                        {
                            c.Item().Border(1).Height(70).Text("").AlignCenter();
                            c.Item().Text("Huella Dactilar").AlignCenter();
                        });
                    });
                });
            });
        }).GeneratePdf();
    }
}
```

### 4.3 Captura de imagen con WebRTC

```jsx
import Webcam from 'react-webcam';
import { useRef, useCallback } from 'react';

const videoConstraints = {
  width: 1280,
  height: 720,
  facingMode: "environment"  // cámara trasera en tablet
};

function CameraCapture({ onCapture }) {
  const webcamRef = useRef(null);

  const capture = useCallback(() => {
    const imageSrc = webcamRef.current.getScreenshot();
    // imageSrc es base64; convertir a blob y enviar al backend
    onCapture(imageSrc);
  }, [webcamRef]);

  return (
    <>
      <Webcam
        audio={false}
        screenshotFormat="image/jpeg"
        screenshotQuality={0.95}
        videoConstraints={videoConstraints}
        ref={webcamRef}
      />
      <button onClick={capture}>FOTOGRAFIAR DNI</button>
    </>
  );
}
```

### 4.4 Principios de diseño UX para el entorno de RH

- Fuentes grandes (mínimo 16px), botones grandes (fáciles de tocar en tablet)
- Colores de estado: verde (OK), amarillo (revisar campo), rojo (error)
- Sin jerga técnica: el operador nunca ve "error 422", solo "No se pudo leer el DNI"
- Flujo estrictamente lineal: Paso 1 → Paso 2 → Paso 3 → Nuevo contrato
- Responsive: funciona bien en tablet (768px+) y monitor de escritorio
- El botón de imprimir es el elemento más grande y visible de la Pantalla 3

## ✅ FASE 5 — Integración, Piloto y Pruebas
**Duración estimada:** 1–2 semanas  
**Objetivo:** Probar el sistema completo con trabajadores reales en condiciones reales, detectar y corregir errores antes del despliegue general.

### 5.1 Casos de prueba obligatorios

| Caso | Descripción | Resultado esperado |
|---|---|---|
| DNI nuevo (electrónico, fondo dorado) | Tipo de DNI más común hoy | Lectura exitosa sin correcciones |
| DNI antiguo (azul) | Todavía en circulación | Lectura exitosa, puede requerir más contraste |
| Nombre muy largo (>30 chars) | Ej: "MARIA DE LOS ANGELES" | Se captura completo sin truncar |
| Dirección muy larga | Más de 60 caracteres | Se captura completa o avisa para verificar |
| Foto con poca luz | Tomada en oficina con luz artificial | Preprocesamiento compensa, lectura correcta |
| Foto con leve ángulo (< 10°) | Error de encuadre común | Deskew corrige, lectura correcta |
| DNI desgastado o rayado | Documento en mal estado | Sistema avisa; fallback a ingreso manual |
| Doble foto (necesita refoto) | Primera foto borrosa | Sistema pide nueva foto; segunda intenta OK |

### 5.2 Piloto con grupo reducido

- Seleccionar 1 punto de atención con 1 operador de RH
- Procesar los primeros 50 contratos con el sistema nuevo **en paralelo** al proceso actual
- Registrar por cada contrato:
  - Tiempo total de atención
  - Si fue necesario corregir algún campo manualmente (cuál y por qué)
  - Si hubo que volver a fotografiar (cuántas veces)
- Calcular métricas reales del piloto:
  - Tiempo promedio real vs objetivo (1.5–2 min)
  - Tasa de corrección manual por campo

### 5.3 Umbrales para pasar a producción

- Tiempo promedio por contrato: < 3 minutos
- Tasa de corrección manual en cualquier campo: < 10%
- Tasa de "necesitó refoto": < 15%

### 5.4 Tests de rendimiento

- Tiempo de respuesta del endpoint OCR: objetivo < 3 segundos por imagen
- Tiempo de generación del PDF: objetivo < 1 segundo
- Comportamiento con 3-5 peticiones simultáneas (si hay múltiples puntos de atención)
- Consumo de RAM con el modelo cargado: no debe superar 2 GB

## ⚠️ Riesgos técnicos y mitigaciones

| Riesgo | Probabilidad | Impacto | Mitigación |
|---|---|---|---|
| Modelo no alcanza 95% de precisión con 200 imágenes | Media | Alto | Augmentación de datos (x5); ajuste de hiperparámetros; considerar TrOCR como alternativa |
| Exportación a ONNX pierde precisión vs modelo paddle original | Baja | Alto | Verificar métricas del ONNX contra el modelo original; delta debe ser < 1% |
| Cámara del tablet produce imágenes de baja calidad | Media | Medio | El preprocesamiento compensa en la mayoría de casos; si persiste, evaluar cámara USB de mayor resolución |
| Rendimiento del modelo ONNX demasiado lento en el hardware disponible | Baja | Medio | ONNX Runtime tiene optimización para CPU; si no alcanza, aplicar quantización INT8 al modelo |
| DNI de diseño nuevo sin ejemplos en el dataset | Baja (largo plazo) | Medio | Modelo interno = reentrenar sin costo cuando aparezcan nuevos modelos de DNI |
